# Glossary

{{ page_breadcrumb() }}

Definitions of key terms and concepts used throughout the EAC documentation.

---

## A

### ADR (Architectural Decision Record)

A document capturing an important architectural decision, including context, decision, and consequences. See [Decision Records](./decision-records/index.md).

### Artifact

A file or output generated by the build process (e.g., binaries, libraries, containers). Commands: [get artifacts](./commands/get/artifacts.md), [show artifacts](./commands/show/artifacts.md).

---

## B

### BDD (Behavior-Driven Development)

A development approach using executable specifications written in natural language (Gherkin). See [Specifications](../explanation/specifications/index.md).

### Build Pipeline

An automated sequence of steps that compile, test, and package code. Commands: [pipeline run](./commands/pipeline/run.md), [pipeline status](./commands/pipeline/status.md).

---

## C

### CalVer (Calendar Versioning)

A versioning scheme based on dates (e.g., `module-name/2024.01.15`). Used for module releases. See [Versioning](./continuous-delivery/changelog/versioning.md).

### Category

A grouping of related commands by verb (e.g., `get`, `show`, `validate`). See [Command Taxonomy](./commands/overview/command-taxonomy.md).

### CI/CD (Continuous Integration/Continuous Deployment)

Automated practices for integrating code changes and deploying to production. See [Continuous Delivery](./continuous-delivery/index.md).

### Contract

A YAML file defining module metadata, dependencies, and configuration. Validated against JSON schemas. See [Contracts](./r2r-eac/contracts.md).

---

## D

### Dependency Graph

A representation of module dependencies showing which modules depend on others. Commands: [get dependencies](./commands/get/dependencies.md), [show dependencies](./commands/show/dependencies.md).

### Diataxis

A documentation framework organizing content into tutorials, how-to guides, technical reference, and explanation. See [DR-004](./decision-records/dr004.md).

---

## E

### EAC (Everything as Code)

The principle that all aspects of software development should be defined as code: configuration, architecture, specifications, tests, and infrastructure. See [R2R and EAC Overview](./r2r-eac/overview.md).

### Execution Order

The sequence in which modules should be built or tested based on their dependencies. Command: [get execution order](./commands/get/execution-order.md).

### Extension

A Docker-based plugin for the R2R CLI that provides additional commands. EAC is delivered as the `ext-eac:latest` extension.

---

## G

### Gherkin

A business-readable, domain-specific language for describing software behavior. Uses Given-When-Then syntax in `.feature` files.

---

## M

### MCP (Model Context Protocol)

A protocol enabling LLMs to use EAC commands as tools. See [MCP Server Setup](../how-to-guides/eac/configuration/claude-mcp-setup.md).

### Module

A self-contained unit of code with its own contract, dependencies, and lifecycle. Can be a library, service, command-line tool, or test suite. See [Modules](./r2r-eac/modules.md).

### Module Type

A classification of modules (e.g., `go-library`, `go-service`, `go-commands`). Determines build, test, and deployment behavior.

### Moniker

A unique identifier for a module (e.g., `src-auth`, `eac-commands`). Used throughout commands to reference modules.

### Mono-Repository

A repository containing multiple related modules managed together. See [DR-001](./decision-records/dr001.md).

---

## O

### OSCAL (Open Security Controls Assessment Language)

A standardized format for security documentation and compliance artifacts. Commands: [create risk-profile](./commands/create/risk-profile.md), [create risk-assess](./commands/create/risk-assess.md).

---

## P

### Pipeline

An orchestrated sequence of build, test, and deployment steps. See [Pipeline Commands](./commands/categories/pipeline.md).

---

## R

### R2R (Ready to Release)

An enterprise CLI framework for containerized workflow execution. EAC is delivered as an R2R extension. See [R2R and EAC Overview](./r2r-eac/overview.md).

### Release Gate

A checkpoint in the release process requiring validation before proceeding. See [Quality Gates](../explanation/continuous-delivery/quality-gates/index.md).

---

## S

### SAST (Static Application Security Testing)

Analysis of source code for security vulnerabilities without executing it. Command: [scan sast](./commands/scan/sast.md).

### SBOM (Software Bill of Materials)

A complete inventory of components in a software product. Command: [scan sbom](./commands/scan/sbom.md).

### SemVer (Semantic Versioning)

A versioning scheme using MAJOR.MINOR.PATCH (e.g., `1.2.3`). See [Versioning](./continuous-delivery/changelog/versioning.md).

### Specification

A Gherkin `.feature` file describing software behavior in Given-When-Then format. See [Specifications](../explanation/specifications/index.md).

### Suite

A named collection of tests grouped by purpose (e.g., `acceptance`, `integration`, `smoke`). Commands: [test suite](./commands/test/suite.md), [show suite](./commands/show/suite.md).

---

## T

### TDD (Test-Driven Development)

A development practice of writing tests before implementation code. See [Three-Layer Approach](../explanation/specifications/concepts/three-layer-approach.md).

### Template

A reusable document structure with placeholder variables for generating documentation. See [Templates Commands](./commands/categories/templates.md).

### Trunk-Based Development

A branching strategy where developers work on short-lived branches off a single main branch. See [DR-002](./decision-records/dr002.md).

---

## U

### Unit of Flow

The smallest deployable unit that delivers value independently. See [Unit of Flow](../explanation/continuous-delivery/core-concepts/unit-of-flow.md).

---

## V

### Validation

The process of checking contracts, dependencies, specifications, and code against defined rules. See [Validate Commands](./commands/categories/validate.md).

---

## W

### Worktree

A Git feature allowing multiple working directories from the same repository, each on a different branch. Commands: [work create](./commands/work/create.md), [work merge](./commands/work/merge.md).

### Workspace

An EAC term for a git worktree used for feature development. Enables parallel development on multiple features. See [Work Commands](./commands/categories/work.md).

---

## Command Terminology

### Command Categories

| Category | Description |
|----------|-------------|
| **create** | AI-powered generation of commits, specs, designs, PRs |
| **get** | JSON output for automation and scripting |
| **show** | Human-readable output for interactive use |
| **validate** | Contract and dependency validation |
| **work** | Workspace management (git worktrees) |
| **test** | Testing and test suite management |
| **build** | Module building |
| **pipeline** | CI/CD orchestration |
| **release** | Release management and versioning |
| **scan** | Security scanning (SAST, secrets, vulnerabilities) |
| **serve** | Local development servers |
| **templates** | Template management |
| **update** | Update operations |

### Command Patterns

| Pattern | Example | Description |
|---------|---------|-------------|
| **get vs show** | `get modules` / `show modules` | JSON vs human-readable output |
| **Noun-based** | `modules`, `dependencies`, `files` | Information retrieval |
| **Action-based** | `create`, `update`, `validate` | Operations and transformations |
| **Compound** | `changed-modules-ci` | Specialized variants |

## File and Directory Terms

### Repository Structure

| Term | Description |
|------|-------------|
| **`/go`** | Source code for all Go modules |
| **`/out`** | Build artifacts and intermediate files |
| **`/specs`** | Gherkin feature files (specifications) |
| **`/docs`** | Documentation (MkDocs site) |
| **`/.r2r`** | R2R CLI configuration and contracts |
| **`/.github`** | GitHub workflows and CI configuration |
| **`/contracts`** | Module contract definitions (YAML) |

### File Types

| Extension | Description |
|-----------|-------------|
| **`.feature`** | Gherkin specification file |
| **`_test.go`** | Go unit test file |
| **`contract.yml`** | Module contract definition |
| **`.nav.yml`** | MkDocs navigation structure |
| **`CHANGELOG.md`** | Module or repository changelog |
| **`workspace.dsl`** | Structurizr architecture diagram |
